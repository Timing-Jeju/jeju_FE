# UI 복원과 후속 작업 기준

사용자 요청에 따라 PR #6에서 제거하거나 바꾼 화면 요소를 PR #5 반영 상태(`2c38a89`) 기준으로 복원한다.

- 장소 검색: 가볼 만한 장소 제목, 정렬 버튼·선택 시트, 필터 칩을 복원한다. 아직 연결되지 않은 추천 정렬·필터는 실행 시 준비 중임을 안내한다.
- 장소 상세: 사진 표시 점, 복사 표시, 전화하기·지도보기·홈페이지 액션 행, 기존 이용 안내 행, 찜 버튼 문구를 복원한다. 미제공 정보는 실제 데이터로 만들지 않는다.
- 지도: 주변 장소 카드의 이미지·캡션·거리 행 배치를 복원하고 미지원 상태를 표시한다. 하트는 상세 화면으로 이동하지 않고 canonical ID로 즉시 찜·해제한다.
- 세 화면의 `StyleSheet` 정의는 기준 커밋과 동일하다. 실제 API·canonical ID·오류 처리·추가 페이지 조회는 유지한다.

임시 장소, 허위 거리, 영업 중·무료 기본값과 임시 일정 계산은 복원하지 않는다. 인증 및 생성 기능의 준비 상태 차단을 해제하는 작업도 아니다. 찜의 서버 동기화는 여전히 후속 작업이며 앱 상태에만 보관된다.

타입 검사, 린트, 기존 55개 테스트와 OpenAPI 생성 일치 검사를 수행했다. 상세 화면 기존 테스트에는 복원한 액션·정보 행 확인도 포함한다. 실제 iOS/Android 기기 화면 비교는 미실행이므로 완전한 시각적 동일성을 검증했다고 표현하지 않는다.

후속 API 연결은 기존 UI/UX를 유지한다. 화면 구조·스타일·동선을 변경해야 하는 경우 먼저 사용자에게 변경안을 설명하고 명시적인 동의를 받는다.

## 추가 점검: 최초 통합 전 디자인 기준

사용자가 UI 변경 금지를 재확인했으므로 비교 범위를 최초 통합 이전 PR #4 커밋 `3c280a1cc05c73150e6f0bb1174443906de04f91`까지 넓혔다. 실제 값·미제공·준비 중 안내와 오류 복구 등 필요한 UX는 기존 UI 안에서 보강한다.

- 검색의 별도 더 보기 버튼을 제거하고 기존 목록 스크롤에 pagination을 연결했다. 연속 스크롤 요청은 하나만 전송한다. 실패 후 자동 반복하지 않으며 기존 검색 버튼으로 재검색할 수 있다.
- 지도 검색 오류는 기존 Alert로 표시한다. 숙소 로딩은 기존 입력 placeholder를 사용한다. 화면 위아래에 무스타일 문구를 추가하지 않는다.
- 로그인 서버 오류는 기존 입력 오류 자리에 표시한다. 여행 조건의 앱 내 임시 보관 안내는 저장 시 Alert로 전달한다.
- 장소 상세는 로딩·실패에도 기존 이미지·본문·뒤로가기·하단 버튼을 유지한다. 미조회 데이터는 찜에 저장하지 않고 기존 하단 버튼으로 재시도한다.
- 일정 로딩의 원래 이미지·간격·진행 막대 디자인을 복원하되 가짜 진행 애니메이션과 자동 성공 이동은 제거한 상태를 유지한다. 기존 안내 문구를 눌러 입력으로 돌아간다.
- 검토·구간 상세는 원래 헤더·빈 상태, live는 원래 지도·패널로 복원한다. 비활성 기능은 모의 결과·안전 판정·위치 요청·경로 호출을 하지 않는다. 데이터 없는 live 상태는 기존 mono 태그로 미제공을 표시한다.
- `npm run ui:check`는 원본 58개 파일의 StyleSheet AST를 비교한다. CI에 포함했으며 승인 없이 기준값을 갱신하지 않는다. constants/assets/기존 공용 UI 컴포넌트 변경도 없다. 이 검사는 JSX 구조·기기별 렌더링의 시각 비교를 대체하지 않는다.

검증: 59개 테스트(12 suites), 타입, 린트, OpenAPI 및 스타일 비교 통과. 네이티브 시각 비교는 `xcrun simctl` 사용 불가 및 `adb` 부재로 미실행이다. 웹 화면 검증도 실행하지 않았다. 따라서 앱 전체의 픽셀 동일성을 주장하지 않는다.
